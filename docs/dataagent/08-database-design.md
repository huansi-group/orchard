> 版本：v1.0（2026-11-04）  
> 上游：[05 Phase 1](05-detailed-design-phase1.md)、[06 Phase 2](06-detailed-design-phase2.md)、[07 Phase 3](07-detailed-design-phase3.md)  
> 说明：各期完整 DDL 在对应分期文档；本文统一命名、类型、索引、迁移、种子数据、容量与回滚约定，避免各期各写一套。DDL 可直接作为迁移脚本评审起点；本文不含代码改动。

## 1. 设计约定

### 1.1 数据库与字符集

| 项 | 约定 |
| --- | --- |
| 生产数据库 | MySQL 8.0（默认）；PostgreSQL 15+ 作为备选 |
| 开发/测试 | H2 2.x（MySQL 模式）；生产不使用 H2 |
| 字符集 | `utf8mb4`；排序 `utf8mb4_0900_ai_ci` |
| 存储引擎 | InnoDB |
| 时区 | 数据库存 UTC；应用层按用户/任务时区展示 |
| 迁移 | Flyway；生产关闭 `hibernate.ddl-auto=update`，改为 `validate` |
| 命名 | 表/字段 `snake_case`；索引 `idx_`；唯一 `uk_`；外键 `fk_` |
| 主键 | `BIGINT AUTO_INCREMENT`；现有 `app_user`/`data_agent` 保持 |
| 租户 | 所有业务表 `tenant_id BIGINT NOT NULL DEFAULT 1` |
| 软删除 | `deleted_at DATETIME(3) NULL`；审计/日志表不删除 |
| 乐观锁 | 可编辑聚合加 `version INT NOT NULL DEFAULT 0` |
| 枚举 | `VARCHAR` + 应用校验；不使用 MySQL `ENUM`，便于演进 |
| JSON | MySQL `JSON`；PostgreSQL `JSONB`；只存结构化快照/配置 |
| 金额/比率 | `DECIMAL`，不用浮点 |
| 布尔 | `TINYINT(1)`；字段名用 `enabled/is_xxx` |

### 1.2 公共字段

大多数业务表包含：

```sql
tenant_id   BIGINT       NOT NULL DEFAULT 1,
created_by  BIGINT       NULL,
created_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
updated_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                            ON UPDATE CURRENT_TIMESTAMP(3),
deleted_at  DATETIME(3)  NULL
```

例外：

- 审计/日志表（`sql_audit_log`、`audit_event`、`scheduled_task_run`、`etl_run`、`delivery_record`）：只追加，不设 `updated_at/deleted_at`。
- 关联表（`user_role`）：只保留 `created_at`。
- 配置表（`system_config`）：保留 `updated_by/updated_at`。

### 1.3 外键策略

- **聚合内**使用外键：`dataset → datasource`、`table_meta → dataset`、`column_meta → table_meta`、`metric → semantic_model`、`chat_message → chat_session`、`scheduled_task_run → scheduled_task`。
- **跨聚合/高频/审计**不建外键：`permission_grant`、`sql_audit_log`、`audit_event`、`notification`、`usage_record`。
- 外键 `ON DELETE RESTRICT`，不级联删除；删除走软删除/归档。
- 多租户下外键不包含 `tenant_id`，由应用与网关保证；需要时用复合外键（Phase 3 评估）。

### 1.4 索引策略

- 组合索引以 `tenant_id` 开头（如 `(tenant_id, status, next_run_at)`）。
- 高频查询：
  - 会话：`(user_id, updated_at)`、`(session_id, seq)`；
  - 审计：`(tenant_id, created_at)`、`(user_id, created_at)`、`(trace_id)`、`(scheduled_task_run_id)`；
  - 调度：`(status, next_run_at)`、`(owner_id, status)`；
  - 任务运行：`(task_id, scheduled_at)`、`(status, created_at)`；
  - 通知：`(user_id, status, created_at)`；
  - 授权：`(tenant_id, subject_type, subject_key, resource_type)`、`(tenant_id, resource_type, resource_id)`。
- 低基数列（status、type）不单独建索引，必须与租户/时间组合。
- 避免在 `TEXT/JSON` 上建普通索引；需要检索时用生成列/全文索引（Phase 2 评估）。
- 唯一键：资源编码/名称在租户内唯一；删除不释放编码（保留审计可追溯）。

### 1.5 租户与隔离

- 一期单租户，`tenant_id=1`；所有查询默认带租户条件。
- 三期支持：
  - L1 共享库 + 行级隔离（默认）；
  - L2 独立 schema；
  - L3 独立数据库。
- 平台管理员跨租户操作必须显式授权并写 `audit_event`。
- 缓存 Key、对象存储路径、导出文件、推送记录都必须带 `tenant_id`。

## 2. 类型映射

| 逻辑类型 | MySQL | PostgreSQL | H2（开发） | Java |
| --- | --- | --- | --- | --- |
| ID | `BIGINT` | `BIGINT` | `BIGINT` | `Long` |
| 字符串（短） | `VARCHAR(n)` | `VARCHAR(n)` | `VARCHAR(n)` | `String` |
| 长文本 | `TEXT/MEDIUMTEXT` | `TEXT` | `CLOB` | `String` |
| 时间 | `DATETIME(3)` | `TIMESTAMP(3)` | `TIMESTAMP(3)` | `LocalDateTime`/`Instant` |
| 日期 | `DATE` | `DATE` | `DATE` | `LocalDate` |
| 布尔 | `TINYINT(1)` | `BOOLEAN` | `BOOLEAN` | `Boolean` |
| 金额/比率 | `DECIMAL(p,s)` | `NUMERIC(p,s)` | `DECIMAL` | `BigDecimal` |
| JSON | `JSON` | `JSONB` | `JSON` | `String`/`JsonNode` |
| 枚举 | `VARCHAR(16/24)` | `VARCHAR` | `VARCHAR` | `enum` |
| 二进制/密钥 | `TEXT`（密文） | `TEXT` | `CLOB` | `String` |

PostgreSQL 适配：

- `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`；
- `DATETIME(3)` → `TIMESTAMP(3)`；
- `JSON` → `JSONB`；
- `TINYINT(1)` → `BOOLEAN`；
- `ON UPDATE CURRENT_TIMESTAMP` → 触发器；
- `MEDIUMTEXT` → `TEXT`；
- 去掉 `ENGINE/CHARSET/COLLATE`。

## 3. 基线表（现有）

```sql
CREATE TABLE app_user (
  id BIGINT NOT NULL AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(120) NOT NULL,
  display_name VARCHAR(120) NOT NULL,
  password_hash VARCHAR(100) NOT NULL,
  role VARCHAR(20) NOT NULL DEFAULT 'USER',
  enabled TINYINT(1) NOT NULL DEFAULT 1,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_user_username (username),
  UNIQUE KEY uk_user_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE data_agent (
  id BIGINT NOT NULL AUTO_INCREMENT,
  name VARCHAR(64) NOT NULL,
  description VARCHAR(500) NULL,
  data_source_type VARCHAR(20) NOT NULL,
  status VARCHAR(20) NOT NULL,
  owner VARCHAR(50) NOT NULL,
  created_at DATETIME(3) NOT NULL,
  updated_at DATETIME(3) NOT NULL,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

> `V1__baseline.sql` 以当前实体为准；已有库使用 Flyway `baseline-on-migrate`，不要重复建表。

### 5.2 迁移规则

1. **只增不删**：先加列/表，再切流量，最后清理；不在同一次迁移删业务列。
2. **可空优先**：新列先 `NULL` 或默认值；回填后再加 `NOT NULL`。
3. **大表变更**：`sql_audit_log`、`chat_message` 等大表加列使用在线 DDL 或分批回填，避免锁表。
4. **回填脚本**独立于结构迁移，可重跑；记录进度。
5. **验证**：空库全量迁移 + 生产快照副本升级 + 回滚演练。
6. **生产配置**：`spring.jpa.hibernate.ddl-auto=validate`；Flyway 开启；迁移账号与运行账号分离。

### 5.3 数据回填

- `tenant_id=1` 回填所有历史表（Phase 1 默认已带）。
- `app_user.role`：`USER → VIEWER`，管理员保留 `ADMIN`；新增 `DATA_ADMIN/ANALYST/AUDITOR` 由管理员配置。
- `agent_dataset`：按现有 `data_agent.data_source_type` 与试点数据集手工绑定。
- `metric_version`：为每个已发布指标写 V1 历史。
- Phase 2：从 `sql_audit_log` 提取血缘候选；从 `chat_message` 提取已验证查询候选。
- Phase 3：建租户 1，回填角色映射；SSO 用户首次登录 JIT 绑定。

## 7. 容量与性能

### 7.1 目标容量

- 租户：1（一期）→ 100（三期）。
- 用户：100。
- 数据源：10；表：10,000；字段：200,000。
- 会话：100,000；消息：1,000,000。
- SQL 审计：1,000 万/年；任务运行：100 万/年。
- 并发：50 用户、10 并发查询（峰值）。

### 7.2 存储估算

| 数据 | 估算 |
| --- | --- |
| 元数据 | < 1 GB |
| 会话/消息 | 2–5 GB/年（按 2KB/消息） |
| SQL 审计 | 5–10 GB/年（按 1KB/行，含索引） |
| 任务运行/通知 | 1–2 GB/年 |
| 结果文件/导出 | 10–50 GB（对象存储，按保留期清理） |

### 7.3 性能措施

- 分页/游标；禁止 `SELECT *` 大表；列表默认 20 条。
- 大表按时间分区：`sql_audit_log`、`scheduled_task_run`、`delivery_record` 在 Phase 3 评估按月分区。
- 审计写入与查询分离；审计查询只走索引列。
- 连接池：应用 20–50；每数据源 10；查询/ETL/调度独立池。
- 缓存：元数据、权限、指标编译结果；Key 带 `tenant_id + version`。
- 对象存储：大结果/导出/审计归档；数据库只存引用。

## 8. 备份、归档与回滚

- **备份**：每日全量 + binlog（或 PostgreSQL WAL）；元数据库 RPO ≤ 24h（可选 ≤ 15m），RTO ≤ 4h。
- **归档**：审计/运行记录超过保留期归档到对象存储；数据库只保留热数据。
- **回滚**：
  - 应用：功能开关/镜像回滚；
  - 数据库：迁移只增不删，保留上一版本兼容；必要时执行 down 脚本（仅限无数据损失场景）；
  - 数据：发布前快照；回滚不删除审计。
- **演练**：每季度一次恢复演练；记录 RTO/RPO。

## 9. 安全与权限

- 应用数据库账号只授予业务表 `SELECT/INSERT/UPDATE`，不授予 `DROP/ALTER`；迁移账号单独。
- 数据源密码、模型 Key、渠道配置使用 AES-256-GCM 加密；主密钥来自 KMS/环境变量。
- 审计表只允许插入与状态更新；不提供业务删除接口。
- 生产禁止 H2 控制台；关闭 SQL 日志中的敏感参数。
- 数据库连接 TLS；备份加密；对象存储私有读 + 签名 URL。
- 行级隔离测试：每个租户一条“跨租户查询必须 0 行”的自动化用例。

## 10. DDL 评审清单

- [ ] 表/字段命名符合 `snake_case`，无保留字。
- [ ] 主键、唯一键、组合索引以 `tenant_id` 开头。
- [ ] 时间字段统一 `DATETIME(3)` UTC；保留期字段明确。
- [ ] 金额/比率用 `DECIMAL`；布尔用 `TINYINT(1)`。
- [ ] JSON 字段有明确 schema/版本，不存无结构大对象。
- [ ] 外键仅用于聚合内；删除策略 `RESTRICT`。
- [ ] 软删除字段与查询过滤一致；唯一键不因删除产生歧义。
- [ ] 迁移可重复执行/可回滚；大表变更评估锁表。
- [ ] 敏感字段加密；日志/审计不落明文。
- [ ] 空库、已有库、生产快照副本三套环境验证。
