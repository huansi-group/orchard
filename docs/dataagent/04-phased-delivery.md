# 04 分期实施方案：从可用问数到数据闭环

> 文档版本：v1.0（2026-11-04）  
> 上游文档：[02 需求分析](02-requirements-analysis.md)、[03 功能设计](03-functional-design.md)  
> 说明：本文给出三期实施路径、范围、验收、工作量与风险；不含代码改动。

## 1. 分期原则

1. **每期独立可用**：不做“半年后才能看到价值”的大爆炸交付；每期结束都能上线一个真实业务场景。
2. **先回答、再治理、后规模化**：首期解决“问得准、看得懂、管得住”；二期补数据闭环与治理；三期扩场景与规模。
3. **垂直切片**：每期按“数据接入 → 语义 → 会话 → 审计/权限 → 反馈”打通一条链路，而不是按技术模块横向堆功能。
4. **安全底线不后置**：SQL 审计、权限校验、只读连接从首期就存在，避免后期补丁式改造。
5. **可评测**：每期有明确的评测集、验收指标与演示脚本；不达标不进入下一期。

## 2. 分期总览

| 阶段 | 周期 | 主题 | 核心范围 | 退出标准 |
| --- | --- | --- | --- | --- |
| Phase 0 | 2 周 | 准备与试点定义 | 场景、数据、角色、指标、环境、评测基线 | 范围与数据就绪，干系人确认 |
| Phase 1 | 8–10 周 | 可用问数 MVP | 接入、元数据、标注、语义、会话、SQL 审计、基础权限 | 试点用户能稳定问数，安全底线达标 |
| Phase 2 | 8–10 周 | 数据闭环与治理 | 轻量 ETL、质量、血缘、行/列权限、访问审批、评测/坏例 | 数据闭环跑通，准确率与治理达标 |
| Phase 3 | 8–12 周 | 规模化与场景化 | 多源、分享/报告/IM/API、归因、SSO、多租户、成本 | 多部门推广，性能/成本/合规达标 |

> 周期为参考值，按 5 人左右团队估算；数据复杂度、模型选型、合规评审会显著影响实际周期。建议每期预留 15%–20% 缓冲。

## 3. Phase 0：准备与试点定义（2 周）

### 3.1 目标

在写第一行代码前，把“为谁、用什么数据、回答什么问题、怎么算成功”定义清楚，避免做出一个演示很好但业务不用的系统。

### 3.2 工作项

| 工作 | 产出 | 负责人 |
| --- | --- | --- |
| 试点场景选择 | 1–2 个高频、数据相对干净的分析场景（建议：销售/订单） | 产品 + 业务负责人 |
| 数据盘点 | 数据源清单、表清单、数据量、更新频率、只读账号、敏感字段 | 数据管理员 |
| 角色与流程 | 用户名单、角色、审批人、数据管理员 | 产品 + IT |
| 指标口径 | 10–20 个核心指标的定义、公式、负责人 | 业务 + 数据 |
| 评测基线 | 50 个真实问题 + 期望答案/SQL（可先人工） | 业务 + 数据 |
| 环境与合规 | 部署形态、网络、模型选型、数据边界、合同 | IT + 安全 |
| 成功指标 | [02 第 2.2 节](02-requirements-analysis.md#22-成功标准试点-3-个月)指标的目标值确认 | 产品 + 业务 |

### 3.3 退出标准

- 试点部门、数据源、核心表、指标负责人明确；
- 只读账号可用，敏感字段清单完成；
- 50 个评测问题完成，至少 30 个有标准答案；
- 部署环境与模型方案确定；
- 业务方书面确认首期范围与不做的内容。

### 3.4 关键决策（默认值）

| 决策 | 默认选择 | 说明 |
| --- | --- | --- |
| 部署形态 | 单租户私有化 | 数据边界清晰；SaaS 留到三期 |
| 试点场景 | 销售/订单分析 | 数据相对完整、问题高频 |
| 数据源 | MySQL + PostgreSQL + CSV/XLSX | 覆盖多数中小企业 |
| 模型 | 现有 DashScope `qwen-plus`，经模型网关 | 可切换私有模型；不绑定单一厂商 |
| 身份 | 本地账号 + JWT | SSO 三期 |
| 首期角色 | Admin / Data Admin / Analyst / Viewer | Auditor 可在二期加入 |

## 4. Phase 1：可用问数 MVP（8–10 周）

### 4.1 目标

让试点业务用户在不写 SQL 的情况下，稳定回答“多少、趋势、对比、排名、拆解”类问题；每个答案可展开 SQL、口径与数据来源；所有查询可审计、受权限控制。

### 4.2 范围

**包含**：

- 数据接入：MySQL、PostgreSQL、CSV/XLSX；连接测试、Schema 导入、手动同步（DS-01～DS-04）。
- 元数据：表/字段标注、标签/敏感级别、检索（META-01、META-02、META-06）。
- 语义：数据集、维度、度量、指标、语义编译（SEM-01～SEM-04）。
- 会话：会话管理、意图/澄清、元数据问答、数据查询、多轮、图表、解读、错误处理、反馈（CHAT-01～CHAT-08、CHAT-10）。
- 审计：SQL 全量记录、检索与详情（AUD-01、AUD-02）。
- 权限：角色、资源授权、列级基础脱敏、智能体范围、SQL 网关（PERM-01、PERM-02、PERM-03、PERM-05、PERM-07）。
- 反馈：反馈分类与记录（EVAL-01）。
- 前端：问答页、数据接入、元数据标注、语义指标、审计、权限基础页。
- 基础设施：元数据库、查询网关、连接池、日志、监控、备份。

**不包含**（放到二期）：

- 定时同步、增量同步（DS-05）；
- 轻量 ETL、质量规则（ETL）；
- 表/字段血缘（LIN）；
- 行级权限、访问审批（PERM-04、PERM-06）；
- 列级脱敏自定义策略（PERM-03 增强）；
- 已验证查询、评测集、坏例闭环、运营看板（SEM-05/06、EVAL-02～EVAL-05、OPS）；
- 导出/分享（CHAT-09）。

### 4.3 交付物

| 类别 | 交付物 |
| --- | --- |
| 产品 | 页面原型、交互说明、验收用例 |
| 后端 | 数据源/元数据/语义/会话/审计/权限模块；SQL 网关；查询执行器 |
| 前端 | 问答页、数据接入向导、标注工作台、指标编辑、审计列表 |
| 数据 | 试点数据接入、30+ 表元数据、10+ 指标、50 个人工评测问题（表格维护） |
| 文档 | 部署手册、管理员手册、用户手册、API 文档 |
| 运营 | 试点用户培训、反馈渠道、每周复盘 |

### 4.4 验收标准

| 维度 | 标准 | 验证方式 |
| --- | --- | --- |
| 功能 | 试点用户可完成“提问 → 答案 → 图表 → 追问 → 查看 SQL” | 演示脚本 + 用户试用 |
| 准确率 | 50 题评测集正确率 ≥ 70% | 人工评分 |
| 执行 | SQL 执行成功率 ≥ 95% | 审计统计 |
| 安全 | DDL/DML 100% 拦截；越权表/列 100% 拒绝 | 安全测试用例 |
| 审计 | 100% SQL 有记录；可按用户/时间检索 | 抽查 + 自动化 |
| 脱敏 | L3 字段默认脱敏；L4 默认隐藏 | 用例验证 |
| 性能 | 简单问题 P95 ≤ 20 秒；50 并发无崩溃 | 压测 |
| 体验 | 试点用户满意度 ≥ 3.5/5；周活跃 ≥ 50% | 问卷 + 埋点 |
| 稳定 | 连续运行 5 个工作日，无 P0 故障 | 试运行 |

### 4.5 演示脚本（验收现场）

1. 管理员接入 MySQL，导入 30 张表，完成 10 张核心表标注；
2. 定义“销售额/订单数/客单价”三个指标；
3. 业务用户提问“上个月华东区销售额是多少？”→ 得到数值、趋势、口径、SQL；
4. 追问“按品类拆开”“和上月比呢？”→ 上下文保持；
5. 提问“客户手机号是多少？”→ 默认脱敏/拒绝；
6. 安全员在审计页找到上述 SQL，查看执行人、耗时、行数、权限快照；
7. 用户点踩“口径不对”，反馈被分类记录（二期接入坏例闭环）。

| W3–W4 | SQL 网关 + 权限 + 审计 | 只读、校验、改写、审计 |

## 5. Phase 2：数据闭环与治理（8–10 周）

### 5.1 目标

把“接入 → 同步/ETL → 元数据 → 标注 → 语义 → 血缘 → 问答 → 反馈”串成闭环；让数据可追溯、质量可度量、权限更细、答案能持续变准。

### 5.2 范围

**包含**：

- 同步增强：定时/增量同步、字段映射、重试（DS-05）。
- 轻量 ETL：SQL 转换、物化、线性编排、调度、运行历史（ETL-01～ETL-04）。
- 数据质量：规则、结果、认证门槛（ETL-05、ETL-06）。
- 元数据增强：术语表、标注工作流、资产认证（META-03～META-05）。
- 血缘：表级/字段级、图谱、影响分析（LIN-01～LIN-04）。
- 语义增强：已验证查询、指标权限（SEM-05、SEM-06）。
- 会话增强：导出/分享（CHAT-09）。
- 审计增强：风险规则、操作审计、留存/导出（AUD-03～AUD-05）。
- 权限增强：列级策略增强、行级权限、访问审批（PERM-03 增强、PERM-04、PERM-06）。
- 反馈与评测：坏例闭环、评测集、回归、质量看板（EVAL-02～EVAL-05）。
- 运营：看板、告警、模型/成本、系统配置（OPS-01～OPS-04）。

**不包含**（放到三期）：

- 更多数据源（SQL Server/Oracle/ClickHouse/Doris/API）；
- 定时报告、IM、嵌入/API；
- 归因/预测；
- SSO、多租户。

### 5.3 交付物

| 类别 | 交付物 |
| --- | --- |
| 数据 | 10+ ETL 任务、5+ 质量规则、20+ 表血缘、100 题评测集 |
| 后端 | 同步/ETL/质量/血缘/评测/运营模块；行/列权限；访问审批 |
| 前端 | ETL 编辑器、血缘图谱、评测/坏例、运营看板、权限矩阵 |
| 文档 | 数据管理员手册、指标治理规范、审计与权限操作手册 |
| 运营 | 坏例周会、月度评测、发布门禁 |

### 5.4 验收标准

| 维度 | 标准 | 验证方式 |
| --- | --- | --- |
| 数据闭环 | 一条“源表 → ETL → 数据集 → 指标 → 问答”链路可演示 | 演示脚本 |
| 血缘 | 核心链路表级覆盖率 ≥ 80%，核心指标字段级可追溯 | 血缘检查 |
| 质量 | 认证数据集 100% 通过阻断级质量规则 | 质量报告 |
| 准确率 | 100 题评测集正确率 ≥ 85% | 人工评分 + 回归 |
| 权限 | 行级权限用例 100% 通过；L3/L4 脱敏 100% | 安全测试 |
| 审计 | 高风险 SQL 5 分钟内告警；审计留存 ≥ 180 天 | 审计演练 |
| 闭环 | 坏例从反馈到关闭平均 ≤ 5 个工作日 | 坏例统计 |
| 性能 | 复杂查询 P95 ≤ 30 秒；并发 50 | 压测 |
| 采纳 | 试点周活跃 ≥ 60%；满意度 ≥ 4.0/5 | 埋点 + 问卷 |

### 5.5 演示脚本

1. 管理员配置每日增量同步 + 一个订单宽表 ETL；
2. 质量规则发现空值异常，数据集标记“不可信”，问答提示；
3. 血缘图从“销售额”指标追溯到订单表字段，展示影响范围；
4. 业务用户问“本月销售额下降的原因”，系统按区域拆解并给出贡献度；
5. 用户申请查看客户手机号，管理员审批 7 天，到期自动回收；
6. 用户点踩“口径不对”，坏例指派、修复指标、回归通过、关闭；
7. 安全员查看高风险 SQL 告警与操作审计。

| W2–W4 | 同步 + ETL + 质量 | 任务、调度、质量报告 |
| W3–W5 | 血缘 | 表/字段血缘、影响分析 |
| W5–W7 | 行/列权限 + 审批 | 策略、改写、审批流 |
| W6–W8 | 评测 + 坏例 + 看板 | 评测集、回归、运营看板 |
| W8–W9 | 联调/安全/压测 | 测试报告 |
| W9–W10 | 试点扩展 | 培训、复盘、门禁 |

## 6. Phase 3：规模化与场景化（8–12 周）

### 6.1 目标

从单部门试点扩展到多部门；补齐多源、分享、报告、IM/API、归因等场景；在性能、成本、合规上达到可运营水平。

### 6.2 范围

- 多源：SQL Server、Oracle、ClickHouse、Doris、API（按客户需求排序）。
- 交付：定时报告、订阅推送、只读分享、嵌入/API、飞书/钉钉/企业微信。
- 分析：维度归因、时间序列归因、简单预测/What-if（可选）。
- 企业管理：SSO/OIDC/LDAP、多租户/SaaS、配额与计费、审计导出审批。
- 成本与性能：模型路由、缓存、异步大查询、查询队列。
- 评测：更大评测集、自动化回归、发布门禁。

### 6.3 验收标准

| 维度 | 标准 |
| --- | --- |
| 规模 | 100+ 用户、5+ 数据源、3+ 部门；50 并发稳定 |
| 可用性 | 99.5%；模型/数据源故障可降级 |
| 成本 | 单次问答成本可度量；月度预算内；缓存命中率 ≥ 30% |
| 安全 | 多租户隔离测试 0 越权；SSO 可用；审计导出可审批 |
| 采纳 | 月活 ≥ 60%；3 个部门常态化使用 |
| 场景 | 至少 2 个定时报告/IM 场景上线 |

## 7. 每期闭环检查

| 阶段 | 数据闭环 | 回答闭环 | 治理闭环 | 结论 |
| --- | --- | --- | --- | --- |
| Phase 1 | 接入 → 元数据 → 标注 → 语义 | 问 → 查 → 图表 → SQL → 反馈 | 权限 → 审计 | 最小可用闭环 |
| Phase 2 | + 同步/ETL/质量/血缘 | + 已验证查询/多轮/分享 | + 行/列权限/审批/风险 | 完整数据闭环 |
| Phase 3 | + 多源/定时 | + 报告/IM/API/归因 | + SSO/多租户/成本 | 规模化运营闭环 |

**判断标准**：如果某一期结束后，用户仍需人工导数、人工改 SQL、人工查权限，说明闭环未完成，不应进入下一期。

## 9. 验收体系

### 9.1 验收层次

1. **功能验收**：按用户故事/演示脚本逐项通过。
2. **质量验收**：评测集准确率、执行成功率、采纳率。
3. **安全验收**：越权、脱敏、审计、注入、导出用例。
4. **性能验收**：P95、并发、稳定性。
5. **运营验收**：培训完成、手册齐全、告警可用、回滚演练。

### 9.2 发布门禁

| 门禁 | 要求 |
| --- | --- |
| 功能 | P0 用例 100% 通过；P1 无阻塞缺陷 |
| 评测 | 通过率 ≥ 阶段阈值；无新增 P0 安全缺陷 |
| 安全 | 越权/注入/脱敏用例 100% 通过 |
| 性能 | P95 达标；无内存泄漏/连接泄漏 |
| 审计 | 100% SQL 可查；审计写入失败可阻断 |
| 回滚 | 具备一键回滚/功能开关；数据备份可用 |

### 9.3 验收角色

- 业务负责人：场景与准确性；
- 数据管理员：元数据/语义/血缘/质量；
- IT/安全：权限、审计、部署、合规；
- 产品：范围、体验、指标。

## 10. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 数据质量差导致答错 | 高 | 高 | 首期选干净场景；质量规则；答案展示新鲜度/质量；认证门槛 |

| 模型成本/时延超预期 | 中 | 中 | 缓存、小模型路由、上下文裁剪、配额、异步 |
| 数据源不稳定 | 中 | 中 | 熔断、物化、重试、健康检查、降级提示 |

## 11. 上线与运营

### 11.1 试点策略

- 选 1 个部门、5–10 名用户、2 周试点；
- 设 1–2 名业务 champion，负责收集问题与反馈；
- 每周一次 30 分钟复盘：Top 问题、错例、口径、权限；
- 试点结束做 go/no-go：准确率、活跃、满意度、安全。

### 11.2 培训与文档

- 业务用户：30 分钟上手，学会提问、追问、看口径、反馈；
- 数据管理员：2 小时，学会接入、标注、指标、权限、审计；
- 管理员：部署、备份、模型配置、故障处理；
- 提供“推荐问题清单”和“常见错误示范”。

### 11.3 运营节奏

| 频率 | 动作 |
| --- | --- |
| 每日 | 数据源/同步/审计/错误率巡检 |
| 每周 | 坏例复盘、Top 问题、权限申请 |
| 每月 | 评测回归、成本分析、指标口径评审 |
| 每季度 | 路线图、模型/数据源评估、安全演练 |

### 11.4 回滚与应急预案

- 功能开关按模块灰度；新版本先 10% 用户；
- 元数据库每日备份；发布前快照；
- 模型/数据源故障降级到缓存/物化/历史；
- 审计失败直接阻断查询；
- 安全事件按“阻断 → 取证 → 通知 → 修复 → 复盘”处理。

## 12. 范围外与后续演进

**本期不做**：自研模型、完整湖仓、实时流、复杂 DAG、MDM、ML 平台、原生 App、数据交易。

**后续可演进**：

1. 数据开发 Agent：自然语言建表、写 ETL、调度发布（需更强权限与人工确认）。
2. 多智能体：分析 Agent + 治理 Agent + 运维 Agent 协同。
3. 主动分析：指标监控、异常检测、自动日报。
4. 数据产品化：对外 API、嵌入式分析、行业模板。
5. 多租户 SaaS：配额、计费、隔离、合规。

## 13. 结论

对中小企业，DataAgent 的成功标准不是“功能多”，而是**用得起、答得准、管得住、能变好**。本方案用三期把复杂度拆开：

- **Phase 1** 用最小闭环证明业务价值；
- **Phase 2** 用数据闭环与治理把“可用”变成“可信”；
- **Phase 3** 用规模化能力把“试点”变成“常态”。

每期都以真实业务场景、评测集与安全验收为门禁，避免做成“演示系统”。
